PURCHASING SUPPLIER EVALUATION SYSTEM - PO STORAGE ENHANCEMENT

This is an overlay patch. Copy/extract the files into the existing project root.
It does NOT contain .git, node_modules, .next, or environment secrets.

Main changes:
1. PO Generator is now PO Storage in the visible UI.
2. Official PO uploads go directly to Cloudinary.
3. PDF POs can be multi-page. Multiple page images can also be selected together.
4. Stored PO documents/pages are saved as metadata in Firestore and reused by the evaluation link/email.
5. Resend uses the stored Cloudinary URL(s) as email attachments.
6. Requisitioner email is auto-resolved from the Employee Google Sheet by name both in the UI and again on the server before sending.
7. Expected delivery, actual delivery, PO status, and received-by fields are read from the PO sheet and shown in PO Storage and the requisitioner page.
8. Role criteria remain aligned with the supplied Apps Script: Purchasing has 5 criteria including compliance; Requisitioner and AMD have 4 criteria.
9. Search/form textbox visibility fixes are included.
10. Cloudinary setup variables are added to .env.example.

Required before upload works:
NEXT_PUBLIC_CLOUDINARY_CLOUD_NAME
NEXT_PUBLIC_CLOUDINARY_UPLOAD_PRESET

The upload preset must be an unsigned preset because this implementation uploads documents directly from the browser. Do not put a Cloudinary API secret in NEXT_PUBLIC variables.


LATEST QUEUE COMPLETENESS FIX
- The PO Storage / For Supplier Evaluation queue is now built from PO for Evaluation + PRF Details v2 + the V2 source-of-truth POs/Items/Requests sheets.
- PRF records with a PO number are linked into the PO queue.
- The 200-record client cap was removed so a valid older record is not hidden from search.
- A PO is removed from For Supplier Evaluation only when an explicit requisitioner evaluation is submitted; a non-requisitioner/historical row with requisitionerAvg alone no longer hides the PO.
- Example scenario fixed: PRF 106892 can surface PO33439 when that relationship exists in the V2 workbook.
- Existing Cloudinary multi-page storage, Employee email auto-resolution, delivery fields, and role-based evaluation criteria remain in place.

V2 WORKBOOK COMPLETENESS / QUEUE FIX
- The PO lookup now merges records from PO for Evaluation, PRF Details v2, plus the Apps Script source-of-truth sheets POs, Items, and Requests.
- PRF rows containing a PO number are linked into the PO queue, so a PRF search can surface its PO even when the PO was not duplicated into PO for Evaluation.
- The previous client-side 200-record cap was removed from the PO Storage list so older records are not hidden from search.
- A PO is considered completed for the For Supplier Evaluation queue only from an explicit requisitioner evaluation submission. Requisitioner average alone no longer hides a PO.
- Example relationship supported: PRF 106892 -> PO33439, when that relationship exists in the V2 workbook.

DUAL GOOGLE SHEET SOURCE FIX
- The system now treats the Supplier Evaluation workbook and the separate V2 PRF/SRF Monitoring workbook as two complementary sources instead of replacing one with the other.
- Supplier Evaluation workbook remains the primary source for PO for Evaluation, PRF Details v2, requisitioner contacts, and existing evaluation data.
- V2 PRF/SRF workbook is read through its business-unit PRF tabs and contributes PO NUMBER, PRF, requisitioner, department, item, purpose, PO date, delivery date, actual delivery date, received-by, purchaser, and purchasing/PRF status fields.
- PO records are cross-linked by PRF number, so a PO that exists only in the V2 monitoring workbook can still appear in PO Storage.
- Verified from the supplied V2 workbook: PRF 106892 is on `PRF - SISC` and links to `PO33439`, with requisitioner `MARK PABUSTAN` and item `2 3D PRINTER P2S`.
- Requisitioner email lookup now falls back to the `Requisitioner Details` sheet in the Supplier Evaluation workbook when an `Employee` sheet is unavailable.
- `/api/send-evaluation` uses the same Employee/Requisitioner Details fallback when resolving the recipient.
- New environment variables: GOOGLE_SUPPLIER_V2_SHEET_ID, GOOGLE_SUPPLIER_V2_PRF_SHEETS, GOOGLE_SUPPLIER_REQUISITIONER_SHEET.
